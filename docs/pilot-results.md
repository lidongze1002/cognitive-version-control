> ⚠️ **这不是实验。**
> 两个条件都由同一个模型（本助手）扮演，作者同时知道假设、脚本和指标。
> A 组被写成“失败”，C 组被写成“成功”。这些数字只能用来**测试流水线**，
> 不能用来证明 CVC 有效。真实实验见 [`experiment.md`](experiment.md)。

## 1. 试跑设置

- 主题：01 人民币汇率
- 轮数：6（前 6 轮，已包含第 5 轮的冲突事实）
- 条件：
  - **A 基线**：普通对话
  - **C 完整 CVC**：重置协议 + 事实账本 + 概念账本
- 数据：[`../pilots/01-rmb/`](../pilots/01-rmb/)

## 2. 结果

| 指标 | A 基线 | C 完整 CVC | 方向 |
|---|---|---|---|
| `concept_reuse_rate` | **0.500** | **0.412** | C 更低 ✅ |
| `frame_entropy` | 0.822 | **0.934** | C 更高 ✅ |
| `belief_revision_latency` | **None（未修订）** | **0.0** | C 更好 ✅ |
| `cvc_score` | 0.447 | **0.815** | C 更高 ✅ |

**A 组的行为**：承认 6.66 是事实，但把它解释为“短期波动”，继续用“利差 + 水池”维持贬值框架，从未标记旧结论过期。

**C 组的行为**：在第 5 轮同轮标记 F-001 过期，引入 F-002，承认“把利差当成唯一变量”是错的，并用“推力/拉力/拔河”替换旧框架。

## 3. 试跑发现的两个指标 bug

### Bug 1：修订时钟从“旧结论出现”开始

旧定义：

```
latency = 修订轮次 - 旧事实进入轮次
```

C 组在第 2 轮提出“贬值压力”，第 5 轮才看到新事实并修订 → 旧定义算出 **3**，触发“信念粘性”警告。

但模型没有错：第 2–4 轮时，新事实还不存在。**真正该测的是“新证据到达后多久改口”。**

新定义：

```
latency = 修订轮次 - 最近一次事实进入的轮次（不晚于修订轮）
```

C 组第 5 轮新事实进入、同轮修订 → **0**。

### Bug 2：不修订反而得分更高

旧逻辑在 `latency = None` 时给中性分 **0.5**。结果：

- A 组从不修订 → 0.5
- C 组延迟 3 轮 → 0.0

**不认错比晚认错得分高。** 这是方向性错误。

新逻辑：

- 有事实进入、但从未修订 → **0**
- 完全没有事实 → 中性 0.5

修复后，A 组从 0.597 降到 0.447，C 组从 0.515 升到 0.815。

---

## 4. 第二个发现：指标不能单独看

A 组的 `frame_entropy = 0.822`，看起来不差。原因是它每轮都引入一个一次性词（`短期波动`、`水池`），把熵抬高了。

**结论：**

- 熵高不等于发散，可能只是“散”
- 复用率低不等于健康，可能只是“每轮换词但不换框架”
- 必须三个指标一起看，并配合人工评分

这条已经写进 [`metrics.md`](metrics.md) 的注意事项。

---

## 5. 这次试跑不能说明什么

- 不能说明 CVC 在真实模型上有效
- 不能说明阈值 0.4 / 0.7 / 1 合理
- 不能说明 token 成本可接受
- 不能说明其他主题也成立

## 6. 这次试跑能说明什么

- 流水线可以跑通：脚本 → 对话 → 标注 → 指标
- 标注格式可用
- **指标本身有 bug，而且被抓住了**

后者是这次试跑最大的价值。
