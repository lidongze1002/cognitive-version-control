# FAQ

## 这是原创吗？

**零件不是，组合是。** 事实账本、假设追踪、记忆修订、多样性采样都有大量已有工作（见 [`prior-art.md`](prior-art.md)）。

CVC 的贡献是把它们**整合成一套可执行流程**，并定义了两个可计算指标：概念复用率、信念修订延迟。

如果你发现更早的同名或同构工作，请开 issue。

## 它和“记忆”有什么区别？

记忆解决的是“**记住**”，CVC 解决的是“**改口**”。

- 记忆：把过去的内容存起来
- CVC：当新事实与旧结论冲突时，强制标记旧结论过期

一个只会记、不会改的系统，记得越多，错得越久。

## 它和 RAG 有什么区别？

RAG 是“**检索相关内容**”，CVC 是“**管理结论的状态**”。

RAG 会把语义相似的旧文档也检索出来，反而可能强化旧框架。CVC 要求给每条事实加时间戳和状态，冲突时优先用新的。

## 支持哪些模型？

**与模型无关。** 它是一套 prompt + 流程 + 指标，Claude、GPT、Gemini、开源模型都能用。

不同模型的遵从度不同，建议先跑 `prompts/00-reset-protocol.md`，观察 5 轮。

## 一定要写代码吗？

不用。最小可用版本就是一段 prompt。

代码（`eval/convergence_metrics.py`）只用于量化，不是必需品。

## 三个指标的阈值是怎么来的？

目前是**经验值**，不是实验结论：

- `concept_reuse_rate < 0.4`
- `frame_entropy > 0.7`
- `belief_revision_latency <= 1`

v0.2.0 会用标注数据校准。欢迎提交你的数据。

## 它能“消除”收敛吗？

**不能。** 自回归模型的收敛是结构性的。

目标是**可控发散**：该一致时一致，该更新时更新，该发散时能发散。

## 会不会增加很多 overhead？

会。每轮维护账本大约多 10–30% 的 token。

建议只在**长对话、高风险决策、教学**场景使用；日常闲聊不需要。

## 为什么不叫“记忆框架”？

因为“记忆”暗示只存不改。CVC 的核心动作是 **revise**（修订），不是 **store**（存储）。

“版本控制”这个比喻更准确：每次修改都留下记录，旧版本可回溯，但当前版本只有一个。
