# 指标定义

三个指标都只依赖“每轮使用了哪些概念”和“事实何时被修订”，不需要模型内部数据。

---

## 1. concept_reuse_rate（概念复用率）

```
reuse_rate = 重复出现的概念次数 / 概念总出现次数
```

**计算方式**：按轮扫描概念列表；某概念在之前轮次已出现，则这一次记为“重复”。

**示例**

```
第 1 轮: [利差]
第 2 轮: [利差, 水池]
第 3 轮: [利差, 拔河]
```

总出现 5 次，重复 2 次（第 2、3 轮的“利差”）→ `0.4`。

**阈值**

| 区间 | 含义 | 建议 |
|---|---|---|
| < 0.4 | 健康 | 保持 |
| 0.4–0.6 | 开始固着 | 提示换框架 |
| > 0.6 | 严重固化 | 强制禁止复用 |

---

## 2. frame_entropy（框架熵）

对概念出现频次做归一化 Shannon 熵：

```
p_i = count_i / N
H = -Σ p_i * log2(p_i)
H_norm = H / log2(k)      # k = 不同概念数
```

**取值**：`0`（只用了一个概念）到 `1`（完全均匀）。

**阈值**：`> 0.7` 为健康；`< 0.5` 说明框架过于集中。

**注意**：概念越多不一定越好。熵高但概念无关，是“散”，不是“发散”。建议配合人工检查。

---

## 3. belief_revision_latency（信念修订延迟）

```
latency = 修订发生的轮次 - 最近一次事实进入的轮次（不晚于修订轮）
```

**为什么不是“旧结论存在了多久”？**
因为旧结论存在时间长，不代表模型有错——那时新事实还没出现。
真正该测的是：**新证据到达后，模型多久改口。**

**示例**

```
第 4 轮: F-001（贬值压力）进入
第 5 轮: F-002（USD/CNY 6.66）进入；同一轮把 F-001 标记过期
→ latency = 5 - 5 = 0
```

如果第 5 轮没有新事实，直到第 8 轮才修订：

```
→ latency = 8 - 5 = 3
```

**无修订怎么算？**

- 有事实进入、但从未修订 → `latency = None`，综合评分按 **0** 计
- 完全没有事实 → `latency = None`，按中性 0.5 计

**阈值**

| 区间 | 含义 |
|---|---|
| 0–1 | 健康 |
| 2 | 偏慢 |
| ≥ 3 | 信念粘性，需要重置协议 |

---

## 4. 综合评分（可选）

```
score = 0.4 * (1 - reuse_rate)
      + 0.3 * H_norm
      + 0.3 * max(0, 1 - latency / 3)
```

仅用于横向比较，不建议当作绝对标准。

---

## 5. 数据采集建议

最小记录格式（每轮一行）：

```json
{"turn": 1, "concepts": ["利差"], "facts_introduced": [], "facts_revised": []}
{"turn": 2, "concepts": ["利差", "水池"], "facts_introduced": ["F-017"], "facts_revised": []}
{"turn": 3, "concepts": ["利差", "拔河"], "facts_introduced": [], "facts_revised": ["F-012"]}
```

运行：

```bash
python eval/convergence_metrics.py --input data.json
```
