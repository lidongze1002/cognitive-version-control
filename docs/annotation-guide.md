# 标注手册

> 目标：把一段对话转成 `eval/sample_data.json` 那样的结构，让三个指标可计算。

---

## 1. 标注单位

**一轮（turn）= 一次用户输入 + 一次模型输出。**

不要按“一句话”标注，也不要按“整段对话”标注。

---

## 2. 三个字段

每一轮填三个列表：

| 字段 | 含义 | 示例 |
|---|---|---|
| `concepts` | 本轮出现的**框架 / 模型 / 类比 / 关键词** | `["利差", "水池"]` |
| `facts_introduced` | 本轮**首次**出现的事实编号 | `["F-017"]` |
| `facts_revised` | 本轮被标记为**过期**的旧事实编号 | `["F-012"]` |

可选：`note`，记录判断理由（不参与指标计算）。

---

## 3. 什么算“概念”

**算：**

- 解释性模型：`利差`、`供需`、`货币乘数`
- 类比/隐喻：`水池`、`拔河`、`油门刹车`
- 反复出现的关键词：`加息`、`通胀`、`出口`
- 命名框架：`三层账户`、`三账本`

**不算：**

- 纯连接词：`所以`、`但是`
- 一次性的举例（除非它成为后续解释的基础）
- 实体名：`美联储`、`英伟达`（它们是主体，不是框架）
- 数字：`6.66`、`92%`（数字属于事实）

**判断标准：**

> 如果删掉这个词，后面的解释方式会变——它就算概念。

---

## 4. 概念归一化

同一个东西，只记一个标准名：

| 出现形式 | 记为 |
|---|---|
| 利差 / 息差 / 利率差 | `利差` |
| 水池 / 水位 / 蓄水 | `水池` |
| 油门 / 刹车 | `油门刹车` |
| 升值 / 人民币走强 | `人民币升值` |

**规则：**

1. 用最短、最通用的中文词
2. 不区分大小写、单复数
3. 同一轮重复出现只记一次

---

## 5. 事实编号

格式：`F-` + 三位递增数字，全局唯一。

- **首次出现**：进入 `facts_introduced`
- **被推翻**：进入 `facts_revised`（旧编号）
- **同一轮修订**：新事实进 `introduced`，旧事实进 `revised`，延迟 = 0
- **只是补充细节**：不算修订，除非改变方向或超过阈值

**什么算“事实”：**

- 可核验的数值、日期、政策、事件
- 可证伪的断言（“人民币有贬值压力”）

**什么不算：**

- 观点、建议、预测（这些应放进假设账本，不参与指标）

---

## 6. 边界情况

### 6.1 一轮里有多个概念

全部记录。指标会按出现次数计算。

### 6.2 一轮里没有概念

`concepts: []`。这是合法的；`annotate.py --summary` 会把它列出来，方便复查。

### 6.3 概念只在提问里出现

**也算。** 因为模型后续可能会复用用户的框架。

### 6.4 用户重复同一个概念

每轮记一次。跨轮重复会被 `concept_reuse_rate` 捕捉。

### 6.5 事实改了但方向没变

例如从 `6.66` 变成 `6.65`：**不算修订**，除非超过预设阈值（建议 1%）。

### 6.6 旧事实被删除

不要删记录，标记 `revised`。

---

## 7. 标注流程

1. **独立标注**：两名标注者各自完成，不讨论
2. **计算一致性**：Cohen's κ，目标 **> 0.7**
3. **分歧仲裁**：逐条讨论，形成最终版本
4. **记录理由**：分歧点写进 `note`

时间估计：**每轮 2–3 分钟**。一段 10 轮的对话约 25 分钟。

---

## 8. 工具

```bash
# 1. 从原始对话生成空白标注文件
python eval/annotate.py --template raw.jsonl --out annotation.json

# 2. 填完后检查
python eval/annotate.py --check annotation.json

# 3. 找漏填的轮次
python eval/annotate.py --summary annotation.json
```

原始 JSONL 格式：

```json
{"turn": 1, "user": "...", "assistant": "..."}
```

---

## 9. 常见错误

| 错误 | 后果 | 修正 |
|---|---|---|
| 把实体当概念 | 复用率虚高 | 只记框架，不记主体 |
| 每个数字都算事实 | 账本爆炸 | 只记支撑结论的关键事实 |
| 修订拖到下一轮 | 延迟虚高 | 同轮完成修订 |
| 只标模型输出 | 漏掉用户引入的框架 | 用户和模型都标 |
| 事后补标 | 记忆偏差 | 边聊边标，或录音回放 |

---

## 10. 交付格式

最终文件是一个 JSON 数组：

```json
[
  {
    "turn": 1,
    "concepts": ["利差"],
    "facts_introduced": ["F-001"],
    "facts_revised": [],
    "note": ""
  }
]
```

放在 `data/annotations/<conversation-id>.json`，并在 `data/README.md` 里登记主题、模型、日期、标注者。
